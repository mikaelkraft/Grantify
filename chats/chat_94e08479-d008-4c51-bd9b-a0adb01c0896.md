### Part B: Executive Media Kit Modal & Print Isolation (`pages/Sponsor.tsx`, `index.html`, `components/Layout.tsx`)
1. **Modal Header Cut Off Inside Top Window**:
   - **Cause**: Modal backdrop used `fixed inset-0 z-50 flex items-center justify-center overflow-y-auto`. When modal content height meets or exceeds the viewport, Flexbox `items-center` shifts the modal's top coordinate above `y = 0` (negative coordinate space), making the top header unscrollable and clipped off-screen.
   - **Fix**:
     - Backdrop changed to `items-start justify-center overflow-y-auto p-3 sm:p-6 md:p-8` with `my-auto sm:my-6` on the modal card.
     - Modal header given `sticky top-0 z-20 shrink-0 bg-white dark:bg-gray-900 shadow-sm`. This guarantees the header is permanently visible and pinned at the top without being clipped.
2. **Print/Save PDF Producing 8 Pages of Duplicate Copy**:
   - **Cause 1**: The ~1200-line background Sponsor page was in normal DOM flow. When printing, the browser laid out all 8 pages of the background page.
   - **Cause 2**: In CSS print specifications, elements inside `position: fixed` or `position: absolute` containers are treated as repeating page running headers/footers and stamped on *every* printed page!
   - **Fix**:
     - Wrapped normal Sponsor page content in `<div className={showExecutiveKitModal ? 'print:hidden' : ''}>`. When the modal is open, the background page is completely removed from print layout (`display: none !important`).
     - Added `print:p-0 print:m-0 print:max-w-none` to outer page container.
     - Styled modal backdrop with `print:static print:p-0 print:m-0 print:bg-white print:overflow-visible print:block`.
     - Styled modal card with `print:my-0 print:rounded-none print:max-h-none print:overflow-visible print:border-none print:shadow-none print:w-full print:max-w-none`.
     - Added `print:hidden` to close and print buttons.
     - Added compact print typography (`print:text-[10px]`, `print:space-y-3`, `print:p-1.5`) and preserved single-row grids (`print:grid-cols-4` demographics, `print:grid-cols-6` zones, `print:grid-cols-3` packages) to ensure a single, pristine A4 page fit.
     - In `components/Layout.tsx`, added `print:hidden` to headers, footers, promo buttons, AI chatbot, and floating WhatsApp widgets.
     - In `index.html`, added `@media print` rules enforcing `#executive-media-kit-printable { position: static !important; width: 100% !important; max-height: none !important; overflow: visible !important; }` and `@page { size: A4 portrait; margin: 8mm 10mm; }`.

## 5. Review of Flutterwave's Updated Developer Documentation & Integration Alignment

### User Request:
> "see flutterwaves updated docs https://developer.flutterwave.com/docs/getting-started"

### Key Findings from Flutterwave's Official Updated Documentation:
1. **Major Version Release (v4.0.0 vs v3.0.0)**:
   - Flutterwave now documents **v4.0.0** alongside **v3.0.0**.
   - **v4 Architecture (Direct API & OAuth 2.0)**:
     - Authentication: Uses OAuth 2.0 with `client_id` and `client_secret` (`FLW_CLIENT_ID`, `FLW_CLIENT_SECRET`) via token endpoint: `POST https://idp.flutterwave.com/realms/flutterwave/protocol/openid-connect/token` (`grant_type=client_credentials`).
     - Base URLs: Sandbox (`https://developersandbox-api.flutterwave.com`) and Production (`https://f4bexperience.flutterwave.com`).
     - Workflow: Step 1: Create Customer (`POST /customers`), Step 2: Create Payment Method (`POST /payment-methods`), Step 3: Initiate Charge (`POST /charges`), Step 4: Authorize (`requires_pin`, `requires_otp`, `redirect_url`), Step 5: Verify status (`GET /charges/:id`).
     - Webhooks: Sent with `flutterwave-signature` header computed via **HMAC-SHA256** of the raw payload using `FLW_SECRET_HASH` base64-encoded (`crypto.createHmac('sha256', secretHash).update(rawBody).digest('base64')`).
   - **v3 Architecture (Standard Checkout & Hosted Payment Links)**:
     - Authentication: API Secret Key (`FLWSECK-...` or `FLWSECK_TEST-...`) via `Authorization: Bearer <SECRET_KEY>`.
     - Standard Payment Initiation Endpoint: `POST https://api.flutterwave.com/v3/payments`
       - Payload: `tx_ref`, `amount`, `currency: 'NGN'`, `redirect_url`, `customer`, `customizations`, `meta`.
       - Response: `{ status: 'success', data: { link: 'https://checkout.flutterwave.com/v3/hosted/pay/...' } }`.
       - This hosted checkout link handles 3DS Card authorization, Bank Transfer, USSD, OPay, and Mobile Money natively.
     - Verification Endpoint: `GET https://api.flutterwave.com/v3/transactions/:id/verify`.
     - Webhook header: `verif-hash` matching secret hash string.

### Enhancements Implemented in Grantify:
1. **Upgraded Payment Initiation (`backend/handlers/sponsored.js`)**:
   - Replaced static client-side URL generation with the official Flutterwave v3 Standard API call: `POST https://api.flutterwave.com/v3/payments`.

   - Sets `paymentUrl = flwData.data.link` upon successful response.
   - Retains seamless fallback to direct hosted payment link (`https://checkout.flutterwave.com/v3/hosted/pay?public_key=...`) if secret key is omitted or during offline test mode.

4. **Environment & Configuration (`.env`, `backend/handlers/config.js`, `types.ts`)**:
