## 3. Discovered Production Deployment Gaps & Fixes

### Issue 1: Vercel SPA Catch-All Intercepting RSS & Static Verification Files
- **Diagnosis**: In `vercel.json`, the negative lookahead regex and rewrite table only had explicit handling for `/sitemap.xml` and specific static files. Any request to `https://grantify.help/rss.xml`, `/feed.xml`, or `/c8d83fa9b47e4ebaa964f4340d21a243.txt` would be matched by the catch-all SPA rewrite and served as HTML (`index.html`), breaking RSS feed syndication and causing ad network domain verification to fail.
- **Fix Applied (`vercel.json`)**:
  - Added explicit rewrites:
    - `{ "source": "/rss.xml", "destination": "/api/index?path=rss" }`
    - `{ "source": "/feed.xml", "destination": "/api/index?path=rss" }`
  - Updated the negative lookahead regex to bypass:
    - `rss\\.xml`
    - `feed\\.xml`
    - `.*\\.txt` (protects `robots.txt`, `ads.txt`, `c8d83fa9b47e4ebaa964f4340d21a243.txt`, and future verification files)

### Issue 2: Missing RSS Autodiscovery Tags in HTML `<head>`
- **Diagnosis**: Search engine crawlers (Google News, Bing) and feed readers (Feedly, Inoreader) look for `<link rel="alternate" type="application/rss+xml">` tags in `<head>`.
- **Fix Applied (`index.html`)**:
  - Injected autodiscovery link tags:
    - `<link rel="alternate" type="application/rss+xml" title="Grantify - Funding Intelligence RSS Feed" href="/rss.xml" />`
    - `<link rel="alternate" type="application/rss+xml" title="Grantify - Funding Intelligence Feed" href="/feed.xml" />`

### Issue 3: Crawler Directives in `robots.txt`
- **Fix Applied (`public/robots.txt`)**:
  - Added explicit crawler permissions:
    - `Allow: /rss.xml`
    - `Allow: /feed.xml`
