## Topic: Fix Blog Content Editor Horizontal Shift of Detail Input Boxes During Scrolling/Editing

### Problem Reported:
> "the blog content editor while scro;;ing from one end of the content while editing moves with it the whole detail input boxes outside of it horizontally"

### Root Cause Analysis:
1. **Ancestor Horizontal Scrollability (`overflow-x: hidden` / `overflow-hidden`)**:
   - In CSS specification, `overflow: hidden` does **not** disable scrolling; it only hides the scrollbar. Ancestor containers (`<main>` in `Layout.tsx`, Admin dashboard root `div.bg-white`, dashboard content panel `div.flex-1`, post edit card `div#new-post-form`, and the `form` itself) used `overflow-x-hidden` or `overflow-hidden`.
   - Any gesture, swipe, or caret navigation that reached the horizontal boundary caused the browser to assign a non-zero `scrollLeft` to these ancestor containers.
   - When `scrollLeft` of `div.flex-1` or `div#new-post-form` shifted, all sibling grid elements—specifically the **detail input boxes** (Title, Instructions, Author, Author role, Category, Tags, Source Name, Source URL, Publish date, Views, Likes, Loves, Claps, Featured Image URL)—shifted horizontally out of view, cutting off their left sides.

2. **Scroll Chaining from ReactQuill Editor**:
   - Inside `.admin-quill .ql-editor`, horizontal gestures were propagating to parent elements because `.ql-editor` did not restrict horizontal touch actions (`touch-action: pan-y !important;`) or contain overscroll (`overscroll-behavior: contain !important;`).
   - Browser caret auto-scroll (`scrollIntoView`) on edge navigation triggered horizontal translation on the unclipped parent containers.

3. **Unconstrained Width on Inputs and Toolbars**:
   - Several inputs inside `div#new-post-form` lacked `min-w-0 max-w-full`, and the secondary symbol/emoji toolbar lacked `flex-wrap` and `min-w-0` on its inner flex items, allowing minor intrinsic width overflow.

### Solution Applied:
1. **Container Containment with `overflow-x: clip`**:
   - Updated `components/Layout.tsx` `<main>` to use `overflow-x-clip`.
   - Updated `pages/Admin.tsx` dashboard outer card, content area (`flex-1`), `div#new-post-form`, the `form` element, and the Quill container to strictly enforce `overflow-x-clip` and `overscroll-behavior-x: contain`.
   - Added `onScroll` reset guards (`scrollLeft = 0`) on `div.flex-1`, `div#new-post-form`, and `form` to immediately neutralize any programmatic or browser auto-scroll translation.
2. **Editor Isolation in `index.html`**:
   - Updated `.admin-quill`, `.ql-toolbar.ql-snow`, `.ql-container.ql-snow`, and `.ql-editor` with `touch-action: pan-y !important;`, `overscroll-behavior: contain !important;`, and `overscroll-behavior-x: contain !important;`.
   - Set `.admin-quill .ql-editor` to `overflow-x: hidden !important; overflow-y: auto !important;` so internal content never propagates horizontal gestures to the page.
3. **Form Inputs Grid Hardening**:
   - Enforced `w-full min-w-0 max-w-full box-border` across all input fields, select dropdowns, textareas, and secondary toolbar buttons.

### Verification:
- Executed `npm run build`:
  - 2,480 modules transformed.
  - Zero TypeScript or bundling errors (`built in 3m 10s`).

## Part 3: Fix Mouse Wheel Scrolling Block in Admin Dashboard

### Problem Reported:
> "my mouse doesnt scroll on the admin pages but only beside the scroll bars and sidebars hosting the page menu, but once a page there is loaded, its content presence is unscrollable"

### Root Cause Analysis:
1. In `index.html`, `overscroll-behavior: contain !important;` was applied to `.admin-content-area` (the main wrapper of every tab on the Admin dashboard).
2. `overscroll-behavior: contain` locks both X and Y axes, preventing wheel/touch scroll events from propagating (chaining) upward to the document/window.
3. Because the Admin dashboard card expands naturally without a fixed viewport height (`min-h-[500px]`), `.admin-content-area` had no internal scroll room (`scrollHeight === clientHeight`).
4. Whenever the user hovered the mouse over any content in `.admin-content-area`, the browser trapped wheel events on that container and refused to scroll the outer window. When hovering over the sidebar or margins, the mouse was outside `.admin-content-area`, allowing the window to scroll normally.
5. In addition, nested `overflow-y-auto` classes on the dashboard root (`div.min-h-[600px]`) and on `.admin-content-area` created redundant scroll contexts.

### Solution Applied:
1. **Removed all `overscroll-behavior` rules** from `index.html` across `.admin-content-area`, `#new-post-form`, `.admin-post-form`, `.admin-quill`, `.ql-toolbar.ql-snow`, `.ql-container.ql-snow`, `.ql-editor`, and editor tables/code blocks.
2. In `pages/Admin.tsx`:
   - Removed `overflow-y-auto` from the dashboard outer card (line 2093).
   - Removed `overflow-y-auto` from `.admin-content-area` (line 2193), retaining `overflow-x-clip`.
3. Verified compilation with `npm run build` (0 errors, 2,480 modules transformed).
4. Mouse wheel events now cleanly pass through to the document window across all tabs in the admin panel.
