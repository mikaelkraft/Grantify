## Topic: Fix TypeScript Compilation Errors in Admin.tsx for Sponsored Placement APIs

### Problem Reported:
In `pages/Admin.tsx`:
1. Line 498: `Object literal may only specify known properties, and 'isPublished' does not exist in type '{ adHeadline?: string | undefined; adImageUrl?: string | undefined; targetUrl?: string | undefined; ctaText?: string | undefined; placementSlot?: string | undefined; }'.`
2. Line 535: `Object literal may only specify known properties, and 'payerName' does not exist in type '{ providerName: string; providerWebsite?: string | undefined; tierId: number; adHeadline: string; adImageUrl?: string | undefined; targetUrl: string; ctaText?: string | undefined; placementSlot: string; durationDays?: number | undefined; adminNote?: string | undefined; isPublished?: boolean | undefined; }'.`

### Root Cause Analysis:
- In `services/storage.ts`:
  1. `ApiService.updatePlacementCreative` type signature only declared `{ adHeadline?: string; adImageUrl?: string; targetUrl?: string; ctaText?: string; placementSlot?: string }`, lacking the `isPublished?: boolean` field that `Admin.tsx` passes when saving listing creative and placement edits.
  2. `ApiService.adminCreatePlacement` type signature required `tierId: number` and was missing `payerName?: string`, `payerEmail?: string`, `amountCents?: number`, `campaignNote?: string`, and `durationDays?: number` that `directPlacementForm` in `Admin.tsx` supplies.
- In `backend/handlers/sponsored.js`:
  1. `update_placement_creative` action did not extract or persist `isPublished` to `sponsored_listings`.
  2. `admin_create_placement` action did not extract `payerName`, `payerEmail`, `amountCents`, or `campaignNote`, and defaulted amount to 0 instead of accepting custom campaign amounts.

### Changes Made:
1. `services/storage.ts`:
   - Updated `updatePlacementCreative` to include `isPublished?: boolean`.
   - Updated `adminCreatePlacement` signature to include `payerName?: string`, `payerEmail?: string`, `amountCents?: number`, `campaignNote?: string`, and made `tierId` optional (`tierId?: number`).
2. `backend/handlers/sponsored.js`:
   - Updated `update_placement_creative` to persist `is_published` via `COALESCE($7, is_published)` when passed.
   - Updated `admin_create_placement` to properly extract and persist `payerName`, `payerEmail`, `amountCents`, and `campaignNote` into `payer_info` and database columns.

## Part 2: Security & Secrets Exposure Audit
### Audit Findings:
1. **Git Repository & History**:
   - Working tree clean.
   - `.env`, `.tmp_backups/`, `dist/`, and `node_modules/` are strictly ignored in `.gitignore`.
   - `.env` has never been committed to git history.
   - `.env.example` and `.env-mKraft.example` contain only placeholder tokens with no real credentials.
2. **Static Code Analysis**:
   - Zero hardcoded API keys, tokens, database passwords, or private keys across `backend/`, `server/`, `api/`, `pages/`, `components/`, and `scripts/`.
3. **Runtime API Exposure Vulnerabilities Identified**:
   - **Payment Gateway Secret Leak** (`backend/handlers/config.js`): `GET /api/config?type=payment_gateways` has no auth check and returns raw `clientSecret`, `secretKey`, `encryptionKey`, and `secretHash` for Flutterwave, OPay, and PayPal in JSON to any caller (including public visitors to `/sponsor`).
   - **Admin Password Hash Leak** (`backend/handlers/admins.js`): `GET /api/admins` returns all admin usernames and bcrypt `password_hash` strings to unauthenticated callers; `POST /api/admins` allows unauthenticated bulk replacement.
   - **PII Exposure** (`backend/handlers/leads.js` & `backend/handlers/contact.js`): `GET /api/leads?type=applications` (non-stats/public) and `GET /api/contact` return applicant details and contact messages without checking admin session headers.

## Part 4: API Endpoints Hardening & Secrets Redaction
### User Request:
> `patch these API endpoints to redact private keys and secure access`

### Patches Applied:
1. `backend/handlers/config.js`:
   - Added `parseAdminSession` and `requireValidAdmin` helpers.
   - Enforced admin authentication on all `POST` mutations (`type=payment_gateways`, `autoblog`, `ads`, `whatsapp`, `social_links`).
   - In `GET /api/config?type=payment_gateways`, authenticated admins receive the full config, while unauthenticated/public visitors (such as on `/sponsor`) receive sanitized gateway data with all private keys (`clientSecret`, `secretKey`, `encryptionKey`, `secretHash`) completely redacted.
2. `backend/handlers/admins.js`:
   - Enforced `requireValidAdmin` on `GET /api/admins`, and completely removed `password_hash` from the database query and JSON response.
   - Enforced `requireValidAdmin` and Super Admin role (`owner`/`SUPER_ADMIN`) on bulk admin updates (`POST /api/admins`). Existing admin password hashes are preserved safely without exposing them over the wire.
3. `backend/handlers/leads.js`:
   - Enforced `requireValidAdmin` on `GET /api/leads?type=applications` for non-stats/non-public requests, securing applicant PII.
4. `backend/handlers/contact.js`:
   - Enforced `requireValidAdmin` on `GET /api/contact`, securing submitted user messages.
5. `backend/handlers/sponsored.js`:
   - Redacted sponsor PII, billing info, and internal notes from `GET /api/sponsored?what=listings&active=1` for public visitors, returning only public ad creative fields.
   - Enforced admin authentication on `what=listings` when active filter is absent.
6. `services/storage.ts`:
   - Updated client methods (`saveWhatsappConfig`, `setAutoblogEnabled`, `getApplications`, `saveAds`, `getAdmins`, `saveAdmins`, `saveRepaymentContent`, `getPaymentGatewaysConfig`, `getContactMessages`) to forward `X-Admin-Session` whenever an admin is logged in.
